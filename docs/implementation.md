## 追加: 未読優先表示・最新未読を開く（2026-09-18）

## 追加: モデル・推論強度の選択

- `list_models` IPC は main ウィンドウのみ許可。読み取り操作と同じライフサイクルで、ページング付き `model/list` を呼び、所有する子プロセスを回収する。スレッドを resume しない。
- チャット入力欄でモデルと対応する推論強度を選択。モデル変更時に標準強度を選ぶ。既定は上書きなし。未送信の選択はアプリ内でスレッドごとに保持する。
- 明示的な選択は送信接続でもカタログに照合し、不一致なら resume / turn/start 前に未送信エラー。モデルは resume と turn/start、強度は turn/start の `effort` に渡す。readonly / 承認設定は変更しない。
- 一覧失敗時も上書きなしの送信を許可。明示的な選択を検証できない場合は送信を止め、下書きを保持する。送信中も次回の設定を変更可能。送信済みリクエストには影響しない。設定変更だけでは送信や config.toml 更新を行わない。
- 仕様根拠: [公式 App Server のモデル一覧](https://learn.chatgpt.com/docs/app-server#list-models-modellist) とインストール済み Codex 0.153.4 の生成スキーマ。グレードは reasoning effort、service tier は対象外。
- Tauri / Rust スキルの権限分離・明示的エラー・型付き境界を適用。React スキルに沿い、選択の有効性はカタログから導出し、古い取得結果は破棄する。

## 追加: treadcraft 独自の未読管理

- 未読は `updatedAt > read_at`。カードに青い点、未分類・グループ見出しに表示対象の未読スレッド数を表示。Codex自身やZedの既読とは独立。
- SQLite schema v2 に updated_at / read_at と初回同期フラグを追加。v1の分類・会話キャッシュは保持し、初回同期を既読の基準にする。それ以降の新規スレッドは未読。古い同期で更新時刻を巻き戻さない。
- 最新履歴取得は thread/read（本文なし）で更新時刻を取得してから thread/items/list を呼ぶ。画面に取得結果を反映し、前面・可視状態になってから専用IPCでその時刻まで既読にする。取得中に届いた新しい更新を誤って消さない。読み込み失敗・背景表示・Zed起動では既読にしない。
- 既読保存失敗は画面で通知し再試行可能。既読更新・新しい更新の同期はrevisionを進め、古い非同期レスポンスによるバッジの復活を防ぐ。本文は保存しない。
- 判定は秒単位の更新日時ベース。応答追加に限定されず、同秒の変更は検知できない。本文の全件走査や他アプリの既読取得はしない。開いている会話に後から届いた更新は再読み込みが必要。
- Tauri/Rustスキルの権限分離とトランザクション、Reactスキルの非同期レスポンス管理を反映。初期化、新規追加、更新、古い既読通知、再起動、v1移行、画面フォーカス、取得失敗、バッジ件数のテストを追加。

## 改善: 送信エラーの案内

- 再開時の `already has an active writer` は専用の `ThreadInUse` エラーとして返し、「別の Codex 接続で使用中」「今回は未送信」「対象セッションを終了後に送信」と表示。競合元を自動特定したようなアプリ名の断定はしない。
- 送信要求を書き始める前の失敗は `ChatNotSent` と区別。送信開始後の失敗や不明なIPCエラーでは未送信と断定せず、履歴確認ボタンを表示する。
- 未送信なら一時表示の送信メッセージを除去し、入力欄の下書きだけ保持。技術的な詳細は折りたたむ。自動再送・プロセス終了・ロック解除は追加しない。
- Tauri/Rustスキルの型付きエラーとReactの状態管理指針を反映。分類テスト、偽サーバーの再開拒否テスト、UIの文言・下書き・詳細折りたたみテストを追加。

## 追加: 最小チャット送受信

- 右端の入力欄から同じ Codex スレッドへ送信。送信時のみ `thread/resume` → `turn/start` を使用し、`item/agentMessage/delta` と完了本文を Tauri Channel で表示する。クリックによる閲覧と Zed 起動は引き続き送信を起こさない。
- 履歴は最新100項目を取得して時系列表示し、以前の履歴を上に追加する。送信後は最新履歴を再取得する。本文はプレーンテキストで、HTMLは実行しない。
- Enter は改行、⌘ / Ctrl + Enter は送信。IME変換中と空白入力は送信しない。下書きは起動中のみスレッド別に保持し、送信エラー時には消さない。
- 同時送信は1件。送信中はペインを閉じる／スレッド切替を抑止し、ターンID取得後に停止可能。停止とアプリ終了では所有するターンだけに `turn/interrupt` を要求し、最大5秒待って所有する子プロセスを回収する。全体上限10分、開始応答上限30秒。通信失敗時は自動再送せず履歴確認を促す。
- `SendOptions.permission` に応じた sandbox（未指定は `read-only`、選択肢は `workspace-write` / `danger-full-access`）を thread/start・thread/resume・turn/start に適用。書き込み対象はサーバー応答の thread.cwd と一時フォルダ。`on-request` approval、`user` reviewer、environments に local と thread.cwd を指定。サーバー起点の承認や追加入力要求はエラーで拒否し停止する。MCP・フック等の既存設定は引き継ぐため、外部連携の完全な無作用を保証するモードではない。他クライアントとの同時送信はサポートしない。
- IPCの送信／停止権限はメインウィンドウ限定。送信対象は同じ Codex 保存先に属し、キャッシュに存在する非アーカイブスレッドのみ。任意の実行ファイル・履歴パス・権限ポリシーをWebViewから受け取らない。

## 設計からの具体化

- IPC は `get_board` / `mutate_board` / `refresh_threads` の3つ。分類操作はタグ付き Mutation で識別する。
- SQLite は専用常駐スレッドではなく `spawn_blocking` + 単一接続 Mutex で直列化。通信中は DB ロックを保持しない。読み取りもトランザクションで一貫した snapshot を返す。
- 保存上のスレッド ID は Codex 保存先識別子と元 ID の JSON タプル。異なる保存先の同名 ID を区別する。初版には接続先を切り替える UI はない。
- App Server は同期単位で起動し終了する。90秒の全体上限、15秒の RPC 上限、重複同期抑止、終了時キャンセルを設ける。
- 通知はまだ使用せず、一覧照合による同期。欠落から削除を推定しない。
- D&D は HTML の内部ドラッグで実装し、Tauri の OS ファイルドロップを無効にした。実 OS ごとの感触・描画は次の QA 対象。
- アプリ名はユーザー指定の `treadcraft`。識別子 `local.treadcraft.desktop` は開発用。公開前に確定し、変更するなら DB 保存先の移行が必要。
- バンドル配布は無効。開発バイナリをビルドできる構成とし、署名付き配布は別作業。
